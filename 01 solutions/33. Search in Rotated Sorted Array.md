# 33. Search in Rotated Sorted Array

There is an integer array sorted in ascending order (with **distinct** values).`nums`

Prior to being passed to your function, is **possibly left rotated** at an unknown index () such that the resulting array is (**0-indexed**). For example, might be left rotated by  indices and become .`nums` `k` `1 <= k < nums.length` `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]` `[0,1,2,4,5,6,7]` `3` `[4,5,6,7,0,1,2]`

Given the array **after** the possible rotation and an integer , return *the index of* *if it is in* *, or* *if it is not in* .`nums` `target` `target` `nums` `-1` `nums` 

You must write an algorithm with runtime complexity.`O(log n)`
## Approach

O(log n) -> binary search
Nhưng chuỗi không tăng dần, chỉ **chuỗi gốc tăng dần**, **distinct**, chuỗi input đã bị xoay trái k index

Bốc lấy mid, luôn tách mảng làm 2 phần, luôn có ít nhất 1 nửa tăng dần

`[4,5,6,7,0,1,2]` -> mid = 7, left = `[4,5,6]`, right = `[0,1,2]`
`[1,2,3,4,5,6,7]` -> mid = 4, left = `[1,2,3]`, right = `[5,6,7]`
`[6,7,0,1,2,3,4,5]` -> mid = 2, left = `[6,7,0,1]`, right = `[3,4,5]`

**Chứng minh**: 
Vì mảng gốc sorted asc, rồi rotate 1 lần => chỉ có 1 điểm gãy tối đa

Điểm gãy tại `p` => `nums[p] > nums[p + 1]` => luôn tồn tại tối thiểu 1 đoạn tăng dần nằm trái hoặc phải so với mid

Kế hoạch như sau:

**Bước 0**: Kiểm tra mid có phải là target luôn không?, tiết kiệm được vô số bước

**Bước 1: Xác định nửa gãy**

Vì mảng là *distinct* và *left rotated* => càng xoay về trái, số lớn càng dồn về trái

=> `nums[left] <= nums[mid]` thì đoạn `left...mid` không đi qua điểm gãy => nửa trái sorted

ví dụ:
```
[4, 5, 6, 7]
 left      mid
```

Ngược lại, nếu đi qua điểm gãy, nó sẽ có dạng là:

```
[6, 7, 0, 1]
 left      mid
```

tức `nums[left] > nums[mid]`

**Bước 2: Xác định target**

Khi biết đoạn nào sorted, ta sẽ tìm target ở đoạn sorted đó
TH1: `nums[left] <= nums[mid]` tức Nửa trái sorted qua `nums[left] <= target < nums[mid]`

Nếu đúng, target chỉ có thể ở nửa trái =>  `right = mid - 1`, sai thì bỏ toàn bộ nửa trái như tư tưởng của binary search => `left = mid + 1`

TH2: `nums[left] > nums[mid]` tức Nửa phải sorted
tìm target trong nửa phải với  `nums[mid] < target <= nums[right]`, nếu đúng thì tìm với `left = mid + 1`, sai thì tìm bên trái `right = mid - 1`

## Complexity

- Time: O(log n), mỗi loop chia đôi không gian tìm -> lặp log2(n)
- Space: O(1), chỉ dùng var, không dùng arr, stack, recursion, k cấp phát memory phụ thuộc input

## Code

```python
def search(self, nums: List[int], target: int) -> int:
	left, right = 0, len(nums) - 1
	while left <= right:
	    mid = (left + right) // 2
	    if nums[mid] == target:
	        return mid
	    if nums[left] <= nums[mid]:
	        if nums[left] <= target < nums[mid]:
	            right = mid - 1
	        else:
	            left = mid + 1
	    else:
	        if nums[mid] < target <= nums[right]:
	            left = mid + 1
	        else:
	            right = mid - 1
	return -1
```
